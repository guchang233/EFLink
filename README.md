# EF Link · 终末地联机模块

当前源码为 **1.6.0-dev.3 权威架构重构开发分支**，尚未发布可用的完整联机版本。**游戏原生执行、房客个人世界隔离与恢复尚未接通；矿石及其余世界对象没有通过端到端真实双客户端验收，`full_sync_verified=false`。** 房间连通、只读数据或测试适配器结果均不能代替游戏同步验收。

各账号继续使用原生登录与官方网络连接，模组房间不代表同一个官方副本实例。实验模组存在账号处罚及状态异常风险，不能声称官方认可或零封号风险。不读取登录凭据，不伪造奖励、物品、任务或账号进度；未验证版本和原生路径默认停用。

完整持续要求见 [ACTIVE_GOAL](docs/ACTIVE_GOAL.md)，当前代码与证据见 [权威重构记录](docs/AUTHORITY_REFACTOR.md)。重构前的 [v1.6.0-dev.2](docs/releases/v1.6.0-dev.2.md) 与备份分支保留；下方历史功能描述不代表当前分支能力。旧怪物注入、角色/武器实例构造、数值结算、效果回放、直接换图和猜测式恢复已陆续删除。

EF Link 是一个独立的 Windows x64 / Better-Endfield 模块，为终末地 mod 提供局域网房间、玩家连接和通用数据通道，并正在接入统一房主权威层。它自带游戏内 ImGui，不需要 WebUI，也不需要 Minecraft、EndCraft 客户端或桥接协议。

按 **=**（主键盘等号键，可在设置中改为 F1–F12）打开联机菜单：开放房间、自动发现局域网房间、直接连接、收藏服务器、查看玩家、聊天和调整设置。关闭菜单后连接继续运行。

## 安装和连接

1. 已发布的重构前存档可在 Better-Endfield 管理应用中导入 `EFLink-1.6.0-dev.2.zip`；当前重构源码使用独立开发 DLL，不与存档构建混用。
2. 启动终末地，登录并进入可移动的场景。
3. 房主按 = → 开放房间 → 填写房间名称、人数和可选密码 → 开放房间。
4. 好友按 = → 局域网房间 → 加入；也可以在“直接连接”中填写房主的 `IP:端口`。
5. 当前重构分支可连接房间并接收只读状态；自动传送、世界入场与共享玩法未支持。界面明确显示未验收能力，位置状态不代表进入同一世界。

默认游戏端口为 TCP/UDP **47615**；房间发现使用 UDP **47616**。名单、名字、收藏和快捷键保存在 `%LOCALAPPDATA%\EFLink\settings.json`；密码不保存。Windows 防火墙弹窗由玩家自行允许游戏联网。ImGui 绘制数据交给 Unity CanvasRenderer，由游戏当前渲染后端处理；运行时不创建覆盖窗口。独占全屏仍待实机验收。

独立启动环境可设置 `EFLINK_PROFILE_DIR` 为绝对目录，使此实例的 EF Link 偏好保存在该目录的 `settings.json`。游戏和启动器的完整隔离仍由实际多开工具负责。

升级同 ID 的 DLL 后需要正常重启游戏。若安装过旧实验模块 `endcraft.link`，使用新的 `eflink.core` 即可；旧模块的 WebUI 不是本模块的入口。

## 当前范围

提供房间控制、可靠/不可靠传输、聊天、玩家加入离开通知和只读位置/队伍/装备采样。统一对象身份、生命周期、状态版本、纯操作意图、房主 witness、队伍授权及隔离/恢复门禁已接入房间规则；原生游戏适配仍未完成。远端角色、武器、效果、战斗、矿石、机关与副本均不能列为当前已验收能力。

### 历史版本记录

以下是历史构建的记录，不代表当前实验构建已通过完整合作验收。

1.5.6：
- 联机菜单变成可以自由摆放的窗口：拖标题行移动、拖边框或右下角握把缩放（双击右下角握把恢复自适应尺寸）；位置与大小在本局游戏内记住，重新打开菜单会回到原处。
- 菜单不再因切换窗口而消失：Alt-Tab、启动器抢焦点或游戏最小化时菜单保持打开，只有菜单键、"返回游戏"按钮和 Esc 才会关闭它；后台状态下菜单不接收任何输入，不会吞掉点击。
- 窗口被始终夹在画面内：拖动到屏幕边缘会被挡住，分辨率或窗口模式变化后也会重新落回可见区域；窗口最小 880×520，屏幕更小时按实际画面收缩。
- 无头界面测试补上真实鼠标事件：注入按下/拖动/释放验证标题行拖动、越界夹取和右下角缩放，并用反向对照确认这些断言不是空过。

1.5.5：
- **修复 1.5.4 加载即崩溃**：模块初始化时先调用了界面主题、之后才创建 ImGui 上下文，触发 ImGui 的
  "No current context" 断言，玩家看到的是 Visual C++ 运行时错误框（`imgui.cpp:3310`，`ImGui::GetStyle`）。
- 上下文创建、主题与字体改为单一入口 `ui::createContext()`，顺序由结构保证；模块、独立预览窗口和
  无头测试现在走同一条初始化路径，测试会在"进程内无任何 ImGui 上下文"的前提下覆盖该路径。

1.5.4：
- 联机菜单与屏幕 HUD 全套改用同一套 ImGui 设计系统（`src/link_ui_theme.h`）：深色工业风配色、统一字号与间距、DPI 自适应缩放，游戏内面板、HUD 与独立预览窗口共用同一份主题。
- 菜单重排为中心面板 + 左侧导航栏：卡片化分区、状态胶囊、角色/房主徽章、导航项计数、底部状态栏与空状态提示；六页内容按"提示条 → 设置卡片 → 操作行"重新组织。
- 新增可复用控件层（`src/link_ui_widgets.h`）与页面层（`src/link_ui_panel.h`）；窗口尺寸变化时导航行高、面板宽高与页脚预留自动收缩，窗口不再超出画面。
- 状态载荷做了类型安全与长度守卫：字段缺失、类型错误或超长文本都不会影响菜单渲染，也不会把空玩家名写回模块配置。
- 菜单最小可用尺寸为 **1024×600**（此尺寸下导航栏不会出现滚动条）；更小的屏幕上仍保持几何体在画面内。

1.5.3：
- 修复跟随/传送到玩家进副本时误报"未解锁副本"：不再自行检查解锁，交给游戏的进副本流程判断。
- 修复房主退出副本后房客无限读条：同一张地图内以坐标判断到达，最多加载两次，到不了就报错停止。

1.5.2：
- UDP 不通时（例如只转发了 TCP、或转发服务的 UDP 不可用），加入房间 3 秒后玩家状态自动改走 TCP，位置、动作与传送照常可用，延迟略高。设置 / 诊断页显示当前用的是 UDP 还是 TCP。
- 修正菜单快捷键显示（= 键曾显示为 F76）和界面底部的版本号。

1.5.1：
- 修复经 frp（如 SakuraFrp）等端口转发联机时双方一直"等待玩家状态"：转发节点回 UDP 包的来源地址可能与连接地址不同，房客现在按房间编号识别房主的 UDP 握手，并改用实际来源地址。
- 玩家页显示 UDP 是否连通。端口转发需要同时开 TCP 和 UDP 两条隧道，远程端口相同，本地端口与开房端口一致。

1.5.0（两台真实客户端验证）：
- 跟随房主换图与"传送到该玩家"全部走官方流程：跨图时由房客账号用地图界面同款接口（`GameAction.TeleportToPosition`）官方传送到目标地图上离目标最近的自有枢纽，再移动到同一坐标；同图直接移动到同一坐标。不再使用本地换图。
- 跟随进入副本：房主进副本后房间保持可用；房客点跟随后以自己的账号通过官方流程（`DungeonManager.TryReqEnterDungeon`）进入同一副本，房主离开副本时房客也经官方流程退出。需要房客已解锁该副本。
- 联机菜单新增"应急回到四号谷地"：先离开房间，再官方传送到四号谷地的枢纽。
- 等待选择期间，菜单顶部常驻"跟随房主 / 暂不跟随"按钮；跟随或传送失败的原因直接显示在菜单里。
- 房客限制只拦截玩家自己在房间里的私人传送和私人副本，EF Link 发起的官方跟随动作放行。

1.4.1-dev（两台真实客户端验证）：
- 修复房客对房主怪物中键锁敌时画面抽搐：战斗中的怪物，原生服务器移动只会让它朝目标点移动而不是直接定位，导致实际位置每帧落后数米并来回拉扯；现在每帧还会把怪物钉在房主的插值位置上，招式重放期间也照常跟随。
- 联机菜单设置页新增"测试用：本机角色无敌"开关（不保存，重开游戏自动关闭）。它会作废本机干员受到的伤害，仅供联机测试，测试完请关闭。
- 开发开关：所有怪物 AI 只在房主运行（`host_owns_all`），默认关闭。

1.4.0-dev（两台真实客户端验证）：
- 大世界挑战可以一起打：房客端的怪物位置改由客户端原生的服务器移动接口（`SC_MOVE_OBJECT_MOVE` → `EntityManager.ServerMoveEntity`）逐帧设定，不再靠移动指令拖拽，抽搐和瞬移消失，房客的攻击能打中。实测挑战中房客命中 281 次，房主全部结算。
- 同一张地图里的挑战/子玩法不再让联机退出入场状态；副本仍不支持。
- 修复房客闪退：私人怪物在一次入场中只移除一次；和房主同编号的怪，等房客自己那只释放完再生成，并按实例编号区分。
- 带部位的怪物的转移伤害（`ApplyTransferredModifier`）也交给房主结算。
- 已知问题（1.4.0 时）：对房主的怪物按鼠标中键锁定时画面抽搐（1.4.1 已修复）；远端玩家的武器和武器光效、敌人攻击预警特效会消失；移动中的怪两边位置差中位数约 2.6 米；只有房主账号获得掉落。

1.3.0-dev（两台真实客户端验证）：
- 房主世界的怪物（关卡怪、挑战/脚本刷出的波次）以房主的服务器 ID 在房客端原生生成；运行时生成的怪使用房主官方服务器下发的原始数据，只去掉战斗身份并换成当前位置和血量。
- 关卡怪：房客命中、炮塔伤害交给房主结算；怪物在房客端的死亡只跟随房主。
- 挑战/脚本怪：两边出现的怪物和位置一致，但**房客的攻击打不动它们**（命中未转交房主），正在修复。
- 房客发给官方的战斗上报中，涉及房主怪物的部分在客户端生成时即被跳过，不消耗序号；两轮实测泄漏为 0。
- 已知问题：房客打不动挑战怪（因此只由房客打时房主也没有掉落）；怪物位置和血量同步有明显延迟；远端玩家的武器和武器光效、敌人攻击预警特效会消失。

1.2.0-dev 新增房主地图/敌人快照、地图版本隔离、玩家传送请求和世界入场握手。客机的账号怪物与房间怪物分开管理，房间怪物尝试从原生模板独立创建；这一创建流程仍待实机验证。传送接入原生移动和地图加载流程；屏幕标记通过没有鼠标命中目标的 CanvasRenderer 绘制。

当前目标是房客仅发送操作意图，由房主验证并通过原生游戏系统执行，统一同步房主观察到的真实结果。所有对象共用同一权威层，不再由各自补丁维护独立结算。个人官方世界必须隔离并可恢复；对应生产适配器缺失时，操作保持停用。收到快照、看到人物或框架测试通过均不计为完成。

通用规则和真实 localhost socket 的测试只覆盖协议/适配接口，测试适配器不进入游戏 DLL。四人能力、真实世界同步、网络误差与长期恢复验收仍必须按 [完整要求](docs/ACTIVE_GOAL.md) 完成；尚未进行这些验收，不发布完整同步声明。

## 从源码构建

安装 Visual Studio C++ x64 工具、Windows SDK 和 PowerShell 7。使用尚未占用的开发模块编号构建，例如：

```powershell
pwsh -NoProfile -File .\tools\build-cooperation-stage1.ps1 -ModuleId eflink.coop.stage1.1000
```

脚本构建独立 DLL，并运行规则、真实 localhost 网络和 V1/V2 ABI 检查；不会启动游戏。编译后源指纹必须一致。注册、启动和实机验收另行进行；不要覆盖已注册 DLL、恢复包或已发布版本。测试适配器和镜像客户端不能代替真实双客户端或四客户端验收。

## 开发者

模块 ID：`eflink.core`。公共 C ABI：`EFLink_GetApiV1` 与兼容其传输接口的 `EFLink_GetApiV2`。头文件位于 `include/EndfieldLink/EndfieldLink.h`，开发指南见 [docs/SDK.md](docs/SDK.md)，可编译的 Better-Endfield 扩展示例位于 `examples/echo/`。

| 目录 | 用途 |
|---|---|
| `src/link_protocol.h`、`src/link_net.h` | 独立于游戏和 GUI 的通信层 |
| `src/link_world.h` | 游戏线程上的采样、模型加载和姿态显示 |
| `src/link_session.h`、`src/link_entry.h` | 房主快照、入场握手、权限和世界版本 |
| `src/link_gui.cpp`、`src/link_native_gui.h` | 游戏内 ImGui / Unity CanvasRenderer 菜单和 HUD |
| `src/link_ui_theme.h` | 共用 ImGui 主题：调色板、度量、DPI 缩放与 CJK 字体加载 |
| `src/link_ui_widgets.h` | 复用控件：卡片、徽章、胶囊、提示条、按钮、开关、字段 |
| `src/link_ui_panel.h` | 六页菜单布局、文案、模块动作契约与屏幕 HUD 覆盖层 |
| `src/link_imgui_mesh.h` | ImGui 绘制命令转换、裁剪和颜色插值 |
| `src/link_module.cpp` | Better-Endfield 生命周期、控制器和公开 C API |
| `include/` | EF Link ABI 与固定版本的 Better-Endfield ABI |
| `tests/` | 协议、真实回环网络与 DLL 接口测试 |
| `tools/` | 构建、打包、镜像客户端和开发诊断 |
