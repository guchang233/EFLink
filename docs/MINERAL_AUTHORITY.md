# 矿石权威同步：当前实现与实机缺口

2026-10-12，分支 `codex/host-world-interactions`。**任务未完成，矿石同步尚未交付。**

上一轮人物与表现实验已保存到提交 `e2c377b`、标签及预发布 `v1.6.0-dev.1`，草稿 PR #1。该版本明确不包含完整世界交互。

## 两个真实客户端的只读证据

通过独立诊断模块，在原生 `CameraManager.TailLateTick` 上各执行一次资源采样。没有操作窗口、切换房间、修改字段、调用采矿操作或发送账号请求。

两端 `map01 / map01_lv001` 均采到 51 个矿石。51 个对象的关卡逻辑 ID、矿石模板和原生位置完全对应；其中 6 个对象的原生 `m_hpRatioRuntime` 不一致，房主为 6666、8333、1665、8666、6333、5999，客机均为 10000。这直接证明旧实现的矿石仍在各自个人世界独立处理。

实例来源为 `InteractiveDoodadCommonComponent`，不能把 `NatureResourceManager` 的本地分配资源 ID 用作跨客户端身份。当前对已识别矿石使用关卡对象身份，内部原生分配身份只负责撤销过期生命期。动态场景和分级资源没有适配，不会因采集到它们就宣称支持。

原始采样保存在忽略的 `build/cooperation-stage1/ore-reference/resource-census2-0.json`、`resource-census2-1.json`。诊断模块 `eflink.coop.resourceprobe2` 已在两个客户端停用；原联机模块 `.22` 保持运行。

## 已写入代码

- `link_world_resources.h` 从原生管理器读取矿石身份、模板、位置、耐久和采集状态。枚举不完整或身份重复时拒绝替换基线。
- `link_resource_authority.h` 为房主观察到的对象分配独立生命期和状态版本。原生对象替换、回收后复用、原位再生、换图会撤销旧对象权限。
- `link_session.h` 增加房主独占的有界完整资源基线，校验来源、房间、场景代数和协议兼容。加载时立即撤销旧基线，过期基线不可用于操作。
- 采矿请求合同拒绝客机伤害数值或破坏状态，校验发送者和角色归属并去重。确认需要匹配原生接受证明及新的状态版本，同一次变化不能确认两个不同攻击。
- 原生操作、客机应用和恢复适配尚未证明，能力标记保持 `false`。资源基线当前用于诊断，**没有将它写回客机矿石，不能作为修复完成的证据**。

`.26` 独立开发构建及 18 组检查通过，源码、DLL、PDB 和检查记录已保存可恢复包。随后增加的只读诊断入口需以新的构建指纹重新验证；`.26` 包不能代表之后的源码。公开 V1/V2 ABI 没有修改。

## 接下来必须打通的链路

1. 在原生受击入口采到可靠的来源角色、施法和命中身份，客机停止自行改变已绑定矿石，也不能向自己账号上报房主世界的矿石破坏。
2. 房主校验距离、原生对象生命期和施法资格，通过确认的原生采矿入口处理请求。调用成功不能替代结果证明。
3. 接入房主受击反馈和原生交互属性回执，再通过客机原生属性流程应用耐久、裂纹、碰撞、破坏和再生。单纯隐藏对象或播放粒子不满足要求。
4. 保存个人资源的原生状态并保序暂存其官方属性更新，离房、换图中断、断线和停用均需可靠恢复；恢复失败不可释放旧房间操作权限。
5. 两个真实客户端分别攻击同一矿石、同时攻击、破坏、晚加入、重连、加载中断和离房恢复，检查原生状态及官方出站请求。掉落和账号奖励继续由官方结算。

机关、采集物、掉落、工厂、挑战、Boss 和副本仍分别验收，矿石通过也不等于完整世界已通过。
