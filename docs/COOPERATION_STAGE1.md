# EF Link 第一阶段开发验收

本文件记录开发证据，不是正式发布能力清单。各账号继续使用官方登录和官方连接；模组房间同步房主世界，不会把官方账号加入同一个官方副本实例。背包、奖励、任务和解锁由官方服务器处理。

## 可恢复基线与测试入口

- 修改前源码及构建：`build/cooperation-stage1/baseline-20261012.zip`，散列清单 `baseline-manifest.json`。
- 独立开发构建：`tools/build-cooperation-stage1.ps1`。使用不同模块 ID，保持 V1/V2 ABI，避免覆盖已加载 DLL。
- EFML：`D:\EFML\build\native\efml.exe launch --game "D:\Arknights Endfield\Endfield.exe"`；不使用旧 Better-Endfield 双开目录。
- `tools/register-development-module.ps1` 注册单独的开发包；已存在包必须换 ID。
- 正式 `eflink.core` 保持原来的停用状态；不替换正式发行包。

## 当前证据

2026-10-12：EFML 实际客户端进入官方账号游戏；单人房主检查获得角色 `chr_0017_yvonne`、81 根骨骼、原生生命值和地图怪物。晚加载时官方装备全量消息已错过；新增读取现有 `CharInfo.GetWeaponInstData` 并使用当前客户端配置表转换模板编号，实测得到武器模板 3265。此步骤只读，不写入账号背包。

开发版 `.9`：辅助镜像原生角色的 `weapon_loaded=true`、`weapon_error` 为空、模板 3265 已加载。Native `CharBagSystem` 查询只对当前房间持有的独立 `ClientCharInfo` 提供临时结果；武器模型路径从原生模板表获取，不写入账号仓库。可选武器显示状态通过运动数据的保留位发送，保持 V1/V2 结构大小和线路布局，原生显示适配核对了 Hide/Idle/InFight 等枚举及其优先级。辅助状态切换已观察到 Hide=5 与 InFight=1；双端实际持握及攻击过程仍需验收。卸装检查发现原生默认模型回退，已在 `.10` 改为 `UnloadWeapons` 显式释放并通过辅助检查。

开发版 `.8/.9`：实际本机房间传输已产生增量与完整基线。增量按稳定实体编号应用，不按数组下标；完整基线至少每秒发送一次，丢失基线时停止客机操作并等待恢复。可靠队列积压超过 256 KiB 时合并可替换世界状态，关键事件继续走可靠连接。该机制已通过独立重建、真实回环连接和缺失基线恢复测试，尚未进行受控网络 p95 测量。

协议新增 schema 3 与合作合同协商。房主分配实体 `life` 和控制权 `lease`；内部原生分配标识不会发送。控制者切换立即撤销旧权限；移动和怪物施法同时校验身份、权限及事件序号，玩家受伤事件关联目标房间角色。离线测试覆盖重复施法、A→B→A 控制者切换、过期实体命中、角色冒用和无效快照的事务回滚。

## 验收矩阵

开发版 `.10` 已通过辅助卸装检查：模板 0、`weapon_loaded=false`、无武器错误，且适配器记录 `applied=true`。原生失败会保留错误并撤销应用证明，不能仅凭资料收到就标记显示成功。

接续开发加入构建指纹及当前游戏版本协商；协议相同但构建或游戏版本不同，也会撤销合作操作权限。玩家切换角色会换发房间角色身份，旧角色的入场授权不会沿用。技能观察记录使用独立的角色、场景、施法编号和事件序号；开始、正常结束和打断由原生入口观察，目前保持回放停用，尚未完成伤害与资源副作用隔离验收。

开发版 `.13`：13 个独立测试全部通过，构建开始和结束核对同一源码指纹；原生读取当前游戏版本为 `1.5.3`。同一辅助角色完成模板 `0 → 3265 → 0`，房间实体身份不变，三次原生装备应用均无错误，离开后原生房间角色清零。可通过 `tools/check-auxiliary-equipment.py` 重复检查；证据在 `build/cooperation-stage1/auxiliary-equipment-13.json`，不代表第二个真实客户端通过。

`.13` 技能观察实测：在同一关卡使用原生加载入口靠近目标，距目标约 2.9 米的普攻被原生接受；随后观察到同一施法的 `begin` 与 `interrupt`，跟踪记录清零，最后经原生入口恢复原位置。完整记录在 `build/cooperation-stage1/native-cast-13.json`。这证明本机开始/打断观察入口实际执行；正常结束及远端技能回放仍需另行验收。

加载保护接续开发：本机原生加载、世界尚未启动或模式切换期间立即撤销操作证明；取消跟随或战斗同步也立即失去操作权限。同一地图重新加载需要换发场景代数和房间角色身份，不能仅凭地图字符串相同沿用旧授权。快照发送失败会停止房主结算和客机授权，恢复时发送完整基线并重新确认入场。

开发版 `.15`：全部 13 个独立测试通过。`tools/check-native-scene-reload.py` 在一个真实客户端完成同地图原生加载和原位置恢复，两段加载均观察到 `local_scene_ready=false`、操作撤权、角色身份变化；场景代数 `3 → 4 → 5`。证据在 `build/cooperation-stage1/native-scene-reload-15.json`。第一次诊断遇到本地 HTTP 4 秒超时，保留 `native-scene-reload-15-first-attempt.json`；延长该诊断的超时至 12 秒后复测通过。这仍不等同于双端换图、加载中断线或十五轮验收。

恢复路径已改为成功后才删除原始消息或个人怪物记录；原生重放中途失败会保留失败项和后续项，继续阻止房间操作及个人交互，等待重试。独立故障测试确认重试顺序和已确认成功的项不会再次重放。暂存队列受消息数和字节数限制，溢出将退出房间而非静默丢弃先前记录；相关错误和恢复尝试通过世界 JSON 输出。客机个人世界恢复、恢复中再断线和模块卸载期间持续原生失败仍需真实客户端验收。卸载等待结束仍未恢复时会记录日志，当前没有证明该故障路径能够自动完成恢复。

最新开发版 `.16`：14 个独立测试全部通过，构建指纹 `dev/add25036e49600bc4c2715d8e6bdd1bb`。原生部位伤害转移入口补上与主伤害入口相同的隔离判断；同一目标、同一原生修改器的嵌套调用只观察/报告一次，原生计算继续执行。单线程嵌套、不同目标/修改器、指针复用、并发和异常退出的范围测试已通过，真实带部位怪物/Boss 仍需验收。

`.16` 实机重复辅助装备 `0 → 3265 → 0` 和同地图加载/原位恢复均通过，分别记录 `auxiliary-equipment-16.json`、`native-scene-reload-16.json`。这些仍是一个真实客户端及辅助镜像的证据。收尾关闭测试房间，保留开发模块载入；房间角色、显示对象、施法跟踪清零，后台运行设置恢复。可恢复源码和已通过测试 DLL 用 `tools/snapshot-development-build.ps1 -ModuleId eflink.coop.stage1.16` 保存；正式发行包未覆盖。

最新开发版 `.18`：15 个独立测试通过，构建指纹 `dev/78c82191088976dfc03bf8ccef83ee90`。旧的客机数值伤害消息一律拒绝，新的命中声明只携带角色、场景、施法、目标生命周期和命中发生编号，不携带伤害量。重复声明不能通过更换包序号或命中单元再结算。原生 Skill 地址和原生施法编号仅在本机建立映射，不进入网络消息；离线测试覆盖指针复用、角色/场景变化、迟到命中、打断、乱序结束和重复发生身份。

`.18` 不再把现有身份校验当成房主原生伤害复核完成。`host_native_damage_verification` 是明确的合作授权阻塞项，当前生产适配器没有该证明。命中声明只能排队待复核，不会直接扣房主血量；缺少归属的客机原生攻击也不能绕过拦截改变房间怪物血量。原生伤害重执行、结果确认和副作用隔离仍需实现与实机验收。

本轮只准备 `.18` 离线开发包，没有加载到游戏，也没有操作游戏窗口或执行钩子实测。手动步骤见 [原生命中归属检查](MANUAL_HIT_HOOK_TEST.md)，只读采样工具为 `tools/capture-hit-observation.py`。当前已加载的旧开发版未被自动替换。

接续实机入房发现 `.18` 客机闪退，干净进程再次复现同一异常。`.20` 修正原生加载前对象清理、加载期间创建/写入的隔离，以及加载参数的异步引用生命周期。15 个独立测试通过；两个真实客户端完成三轮入房稳定观察和离房对象清理，期间未闪退。证据为 `room-entry-20.json`，详细失败与复测边界见 [入房闪退调查](ROOM_ENTRY_CRASH.md)。双方原生角色与武器均载入；这不是完整战斗同步验收，也未验证初始任务场景、个人世界位置、一小时或十五轮要求。

## 2026-10-12：人物与表现实验存档，完整世界交互仍未完成

新增 `.22`–`.25` 的四人队伍表现、粒子与武器材质显示适配、韧性读写与原生读回、表现帧合并及压缩。`.22` 两个真实客户端已记录双向四个原生角色及武器加载，技能操作出现特效创建与释放计数。计数不能证明全部特效、召唤物或投射物通过；收到一致韧性 JSON 不能证明原生韧性条和战斗延迟通过。

用户实测指出矿石受击反馈、破坏事件未同步。这是完整世界交互的缺口，不属于完成共享世界。开发版本将按对象类别分别记录权威请求、房主执行、确认、客机应用、生命周期与恢复，不再用人物和怪物快照验收代替世界交互验收。具体边界见 `docs/releases/v1.6.0-dev.1.md`。

新一轮已接入原生矿石身份与状态采样、房主独占资源基线、操作请求合同及生命期/去重检查。两个真实客户端采到 51 个身份对应的矿石，其中 6 个原生耐久不一致。当前没有客机矿石状态写回、房主原生操作执行或个人资源恢复证明，仍不能称为矿石同步完成。详见 [矿石权威同步](MINERAL_AUTHORITY.md)。
