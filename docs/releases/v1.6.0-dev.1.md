# v1.6.0-dev.1：人物与表现同步实验版

这是上一轮开发的可恢复版本，不是完整共享世界的完成版本。矿石受击颤动与破坏未接入房主权威链路，不能据此宣称客机已接管房主完整世界。

## 本轮代码改动

- 通过当前原生队伍槽位采样四名成员的模型、成长、武器、持握状态与骨骼，创建独立房间角色；换人、换装、场景失效及离房时重新校验身份并清理。
- 采样并回放战斗粒子、武器挂点特效及材质光效；显示回放不再次调用玩家技能。显示层实例与原生施法、伤害结算分开记录，资源加载、自然回收及释放均保留诊断。
- 房主怪物快照增加韧性值，客机通过原生入口应用；增加原生读回数据，区分收到状态与实际应用状态。
- 人物插值缓冲从固定 100 ms 调整为 50 ms；完整表现帧允许合并待处理旧帧并使用有界无状态压缩。施法终止、战斗证据及世界增量保留顺序。
- 保留原有 V1/V2 公共 ABI。房间协商构建、游戏版本与内部协议版本，不兼容客户端不进入完整合作状态。
- 保留入房修复：换图前撤销旧场景权限，原生初始化完成前不生成房间角色，异步加载参数保持有效，离房清理可重复执行。

## 已取得的实机证据及其边界

两个真实客户端的开发构建 `.22` 已观察到双向各四个原生远端角色，武器加载成功、骨骼匹配且无角色适配错误；技能操作后两端出现远端特效创建与释放记录。该证据不等同于所有特效资源、投射物、召唤物和材质光效均已验收。

房主与客机世界 JSON 含相同韧性值。韧性变化后的原生条形表现及战斗延迟还需受控复测，不能仅凭 JSON 相同认定完成。

空闲旧版两客户端采样中，客机世界快照年龄中位数约 31 ms，最高 110 ms。这不是攻击结果延迟，也不是 RTT 100 ms、丢包 2% 环境下的验收结果。四人队伍启用后的表现包约 15–17 KB，新增压缩路径将记录实际原始字节与发送字节，不能把压缩测试代替联网延迟验收。

独立测试覆盖协议身份、场景失效、重复事件、资源生命周期、清理、完整状态重建及压缩边界。测试程序不能替代四个真实客户端、一小时运行、十五轮切换或完整世界交互验收。

## 明确未完成

- 矿石受击颤动、耐久、破坏、耗尽与重生，以及客机请求由房主原生入口执行。
- 采集物、机关、可破坏物、掉落显示与完整交互状态恢复。
- 完整的房主原生战斗复核。当前仍保留 `host_native_damage_verification` 门槛；不会改成已完成来绕过验收。
- 任务、副本脚本、工厂等完整世界规则的接管。
- 同一官方副本实例。模组房间不会改变官方实例归属。

账号的背包、奖励、任务、解锁与官方连接仍由官方系统处理。本版本不补造账号物品，不启用独立服务端。

## 下一轮验收入口

以矿石为首个完整交互对象：房主与客机互换攻击者，验证受击反馈、耐久及破坏由房主确认；客机只应用确认结果。随后覆盖同时攻击、重复请求、迟到事件、离房恢复、重连及晚加入。每个对象类别必须分别证明，不能从矿石通过推断全部世界对象已同步。
