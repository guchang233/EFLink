# 武器外观同步：参考分析与第一阶段修改

2026-10-12。用户授权初步修改，并明确禁止启动游戏。本轮仅静态分析、独立 DLL 编译和脱离游戏的测试；未安装或替换运行中的模块。

## 参考代码哪些有用

| 参考内容 | 对当前项目的作用 | 本轮取舍 |
|---|---|---|
| S 的 `CHAR_INFO.weapon_id`、`ITEM_INST`、`WEAPON_DATA` | 确定角色与武器实例的关联，并取得实际武器模板 | 已接入被动观察与关联校验 |
| S 的角色/仓库全量消息，以及现有协议中的增量、换装消息 | 初始化、更新或清除本地装备资料 | 已实现独立缓存 |
| S 的 `skill_info`、场景 `skill_list` | 为后续原生技能初始化提供字段依据 | 保留参考，未改技能流程 |
| S 的推荐武器选择逻辑 | 新建角色时分配初始装备 | 不适用于复制另一位玩家当前装备 |
| S 的账号、登录、存档与完整服务器 | 可构造离线协议样本 | 本轮不接入实际联机架构 |
| S 的原版 `BATTLE_CLIENT_OP_DATA` 与 codec | 与项目比较协议差异 | 不覆盖项目版本；原版缺少已被项目补回的战斗操作载荷 |
| C 的重定向、加密补丁、相机透明与 DLL 代理 | 连接其服务端时的客户端适配 | 本轮无直接用途，没有武器挂接或特效复制实现 |

S 的固定提交已经记录在项目的 `server/vendor/lr-proto/NOTICE.md`。两份参考的 README 支持游戏 1.5.3，不能据此确认用户当前客户端的原生接口兼容性。此前的完整证据和六项参考测试见 [参考分析](../references/LR-analysis/REPORT.md)。

## 已修改的生产路径

```text
现有 NetBus 接收钩子（原消息继续交给游戏）
  → 本地角色/武器缓存（普通账号 scope=1，武器 depot=1）
  → 读取当前角色已有 CharInfo.instId 字段
  → 校验角色模板、weapon_id、武器实例 ID、equip_char_id
  → 仅生成公开资料 {template, weapon_template}
  → 客机可靠发送给房主
  → 房主校验发送者、角色模型、地图、场景代数
  → 世界快照携带外观资料，其他客机与后加入者可读取
```

主要文件：

- `src/authority/link_official_appearance.h`：被动缓存，全量/增量/删除/换装更新，以及解析错误诊断。
- `src/link_profile.h`、`src/link_realm.h`：严格验证公开外观格式和快照。
- `src/link_session.h`：外观消息、房主转发、过期资料清理和状态输出。
- `src/link_world.h`、`src/link_module.cpp`：现有接收与采样路径接入；没有增加猜测的武器组件调用。
- `tests/link_appearance_test.cpp`、`tests/link_session_test.cpp`：关联、生命周期与真实回环网络验证。
- `tools/build-appearance-offline.ps1`：单独输出开发 DLL 并执行脱离游戏的测试。

角色和武器的账号实例 ID 只用于本地关联。公开资料不含它们、不含账号背包、不含战斗数值或任意资源路径。`weapon_template=0` 表示已观察到卸装，`null` 表示资料不完整，二者区分处理。

同一资料每秒刷新一次，变化立即提交；房主超过三秒未收到有效资料时清除。断线、换角色或换地图后不能沿用旧记录。解析或序列化失败会使缓存失效并留下诊断，后续完整资料可恢复。

外观更新不重建战斗实体，不授予入场或战斗权限，不重置技能状态。

## 当前明确的限制

这是**装备资料同步阶段**。还没有创建/挂接远端武器对象、切换持握/收鞘，也没有回放玩家技能特效，因此不能宣称“互相看不见武器和特效”已经修好。

原生接收钩子是否可安装、当前角色 `instId` 能否对应账号角色、真实客户端消息是否仍符合这些字段，都尚未通过游戏运行验证。模块若在登录全量消息之后加载，可能缺少缓存，需要等待完整资料；本轮没有主动请求账号背包或添加运行时补丁。

S 只有技能初始化的部分依据，缺少完整战斗操作处理。后续特效还需要玩家施法开始/结束/打断、技能归属与实例映射，以及动画/骨骼写入协调。不能只把技能 ID 转发后直接调用 `TryCastSkill`。

状态接口新增 `game.appearance` 和 `world_session.appearances`，明确标记 `stage=metadata_only`、`weapon_applied=false`、`effects_replayed=false`。

## 离线验证与产物

执行入口：

```powershell
& '.\tools\build-appearance-offline.ps1'
```

输出目录为 `build/appearance-preliminary/`。脚本只构建独立模块与 SDK 示例，并运行十个现有/新增独立测试程序；API 测试使用空游戏运行时、关闭 GUI。网络测试使用本机测试房间，未启动游戏或 LR 服务端。

参考测试另外调用原始 S 的角色/仓库生产函数，将消息写入内存，提取两份虚构资料的二进制样本，交给生产 C++ 缓存验证角色 ID 与武器 ID 的交叉关联。

日志：`build-and-tests.log`、`lr-fixture-tests.log`、`lr-appearance-bridge.log`。开发模块：`eflink.core.dll`。修改前的七份现有文件备份保存在 `original/`。

本轮结果：十个独立 C++ 测试程序全部通过；其中新增缓存有 33 项检查，扩展会话测试有 101 项检查，包括客机→房主→客机、房主→客机和后加入者。接入 S 原始消息样本后缓存检查合计 35 项全部通过。S 的六项参考测试全部通过，66 份用于测试的原始源文件哈希复核通过，两份参考仓库保持干净。独立模块编译没有 C++ 警告或错误。

现有发布 DLL、安装位置、版本号和发行包未替换。本轮验证范围只到编译、资料解析、协议和独立模块 API；游戏渲染、资源挂接、真实客户端兼容性仍待后续验证。
