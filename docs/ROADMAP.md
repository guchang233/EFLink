# EF Link 路线图（2026-10-10 重新规划）

目标见 `SERVER_GOAL.md`。本文件记录 2026-10-10 用户选定的架构，以及按该架构推进的阶段。

## 架构：官方锚定 + 房主世界覆盖（方案 A）

- 双方保持各自官方账号在线。不做私服重定向，不做登录或加密绕过。
- **房客的官方账号始终真实地处于房主所在的地图**。进房、跟随换图、离房时，都由房客
  客户端用自己已解锁的传送点向官方发起真实传送，读条、场景加载和"加载完成"回执
  全部是原生、真实的，不伪造换场景消息，也不拦截加载回执。
- **世界内容以房主世界为准**：房客私人世界的实体视野消息被暂存，房主世界的实体以房主
  的真实 ID 经原生 `ENTER/LEAVE_VIEW` 下发（已实现：怪物）。
- **出站分流**：房客在房间内发出的请求按类型分为三类：
  - 放行官方：背包、菜单、角色养成等账号内操作，以及移动（位置合法）；
  - 转交房主：目标是房主世界实体的操作（战斗、交互物、机关、刷怪波次），由房主客户端执行，
    经房主的官方账号结算；
  - 不生成或丢弃：其余针对房主实体、又无法转交的上报。
  战斗上报带连续序号，只能在 `ServerReporter.CreateServerOp` 源头不生成，不能事后删包。
- **奖励只归房主账号**。房客的背包只能由官方服务器发放，EF Link 不伪造奖励。
- 副本暂不支持：进副本是官方的实例请求，房客无法真实进入房主的副本实例。

### 冻结（保留代码，不再接入游戏）

`server/`（Zig 内核与 `NativeAuthority` DLL）、`include/EndfieldLink/NativeAuthority.h`、
`src/authority/native_authority_client.h`、`src/authority/native_scene_ack_route.h`。
它们是为"脱离官方"路线（方案 B）准备的，留给以后的 MC 桥接或拜访模式。现有 C++ 房间
网络（`link_session.h`）继续承担传输。

## 阶段（每阶段以两台真实客户端验收为准）

| 阶段 | 内容 | 验收 |
|---|---|---|
| M0 收口 | 合并 dev80–82 源码改动成一个干净版本；两端冷启动统一版本；提交存档；记录漏报和帧耗时基线 | 两端同版本入场 active，基线存入 `reports/` |
| M1 出站分流 | 在 `HGNetSession.SendMessage` 对房间内房客出站请求分类；先观察一轮建立白名单，再启用转交/丢弃；被丢弃的请求如果客户端等回应，要补原生应答 | 一轮进房、战斗、离房：官方收到的针对房主实体的请求为 0，房客端无挂起请求 |
| M2 原生命中 | 用房客客户端生成的 `DamageAction` 明细（`target_id`、`value`）作为命中来源，替代另行测量；血量试用 `SC_ENTITY_PROPERTY_CHANGE` 回推 | 双方血条一致，死亡只由房主判定 |
| M3 跟随换图 | 房主换图后逐客询问；同意者用已解锁传送点做官方传送，到达后由原生下行接管；离房官方传送回原位并补交暂存消息；未解锁的如实提示 | 接受、拒绝、超时、加载中断线、离房返回 |
| M4 交互物 | 宝箱、机关、掉落以房主世界状态覆盖显示（`SC_SCENE_UPDATE_INTERACTIVE_PROPERTY`、`SC_SCENE_DESTROY_ENTITY`）；房客操作转交房主执行 | 房主开过的箱子在房客端显示已开；房客账号无异常奖励 |
| M5 角色原生化 | 研究原生 Squad/CharBag 流程，替换他人角色的 `0xEF` 替身 | 他人角色走原生生成 |
| M6 Boss 与脚本 | 观察房主关卡脚本、刷怪波次并下发 | 共同完成一场事件战 |

参考：`docs/REFERENCE_CAMPOFINALE.md`（战斗上报、交互物、脚本、波次的消息结构）；
`references/LR-S-current`（当前版本的场景与视野消息）。
