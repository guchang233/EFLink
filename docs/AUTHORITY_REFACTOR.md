## 审计：必须移除的严重问题

1. 旧客机伤害路径先填满目标血量，在客机执行伤害，再恢复血量并上报。即使不信任其伤害数值，也执行了独立本地结算。已删除前后回填路径及对应伤害钩子调用。
2. 旧 `player_hit` 将数值伤害直接用于玩家官方角色，并保留生命值下限 1。这不能表达房主原生受伤、倒地和复活结果，也可能产生账号侧副作用。已删除应用和转发路径；旧消息明确拒绝。
3. 旧客机运行怪物 AI、提交运动状态和技能结果；房主再使用客机模拟的结果。已删除客机上报和房主消费路径。新请求只能是操作意图。
4. 旧客机将快照写入 HP/韧性，并用隐藏尚未死亡的模型近似死亡。已删除这些投影操作，以及旧人工生成敌人的路径。未经原生结果/应用适配证明不得恢复。
5. 旧原生技能回放会执行玩法。已停用玩法技能回放及未经验收的粒子、材质、角色视图创建。显示成功不能认证世界接管。

## 重要的架构问题

怪物、施法和矿石原先分别维护身份与去重，私人世界恢复仅覆盖一部分怪物消息。单独增加矿石状态补丁不能解决跨类别归属、代次和恢复问题。下一阶段将统一对象登记、房间/场景/成员身份、命令去重、原生执行凭证、原生结果版本、完整基线、晚加入及恢复状态机。

第一删除阶段保留网络和只读原生发现；共享世界适配器默认停用。它不是功能完整的联机版本，不替换目前两个客户端运行的旧 `.22`。新界面/世界 JSON 明确报告未支持与账号风险。

## 通用权威层（正在构建，未实机验收）

`src/authority/world_authority.h` 将房间世界 incarnation、场景代数、原生对象 cookie、公开对象身份/生命周期/版本、成员 incarnation 和操作身份分开。原生 cookie 仅留在房主内存，公开基线没有指针、账号 ID 或本地 nature ID。所有共享对象类别通过同一完整枚举、生命周期 journal 和基线进入账本。

客户端意图不允许携带伤害、生命状态、奖励等结果。房主规则检查成员和角色绑定、作用域、目标版本、生命周期及操作去重后，才给经过执行/隔离/恢复认证的原生适配器分配 ticket。执行返回不确认成功；只有该适配器提供的目标/来源/ticket 匹配原生 witness 才提交结果。不相关的后续只读采样不能确认操作。超时、断线、池化复用和换图撤销旧凭证。

删除 `ResourceAuthority` 与 `resource_baseline` 通路，矿石只读扫描改接入统一对象账本。统一基线和增量 journal 经可靠世界通道发送，缺口必须完整基线恢复。当前 transport 只允许只读同步；`world_intent` 在生产环境没有经过认证的适配器，明确拒绝，不可通过 RPC 配置解锁。

修复第一删除阶段漏掉 `Session::update` 的运行时接入，恢复游戏线程消费网络消息。公共 V1/V2 导出不变，合作 contract revision 增加到 10，避免旧矿石协议与新通路混用。

独立测试中的 `fixture-only` 原生适配器只证明房间规则，不能证明游戏版本、账号隔离、原生恢复或双客户端同步。原生执行、客机应用和全同步能力仍为 false。完整要求持续记录于 [ACTIVE_GOAL.md](ACTIVE_GOAL.md)，阶段构建不得作为目标交付。

## 原生采样准备

开发构建 `.34` 关闭整个旧玩法 hook 安装分支，以及会改写原生世界的 owner/travel/self-cast/feed/move 诊断入口。只读相机/资源适配限定到实际检查过的 1.5.3；未知版本在安装游戏 tick 前拒绝，错误在状态中显示，不能绕过游戏版本门禁。只读支持不等于玩法或账号安全认证。

独立 `resourceprobe5` 增加 90 秒、有界 64 条的矿石受击前后只读记录，记录稳定 level key、矿石生命/采集状态和黑板参数名称/类型，不采集参数值、账号身份或登录资料。原生受击函数原样调用一次；探针不发送操作、不改写字段、不阻断个人玩法、不播放效果。此探针用于辨别真实回调/来源，不证明远端执行或恢复。

`.33` 已通过 18 组独立检查（含 49 项通用核心断言），恢复包 SHA256 `EFC0EB9C8F9A155943D1A7B341A0F262CAB1ED4361EAEE9E702EF3A70CB9B436`。`.34` 已通过同样的完整构建、18 组检查及 ABI 验证，额外检查未知游戏版本默认停用。两者都未完成真实双客户端端到端验收；能力标记仍为未支持。

## 恢复规则收紧

`.35` 将恢复门禁的调用者布尔声明替换为原生适配器接口：捕获并保留个人快照，开始共享场景，观察原生初始化，提交并观察基线应用，暂停共享操作，提交并观察个人恢复，最后释放快照。快照句柄只留在原生适配器内存，不能由房客 JSON 或 RPC 提供。加载失败进入恢复；恢复提交返回并不开放个人世界，失败保留快照，重试和轮询不重复执行原生恢复。房间/场景重置不能丢弃已保留快照。该规则仍没有已验收的真实游戏实现，因此不开放原生操作。

新增独立检查覆盖恢复提交与实际观察分离、半完成入场失败、恢复重试、线程约束、journal 保留期耗尽后的完整晚加入及过大枚举的原子拒绝。`.35` 完整 DLL 构建和 18 组检查已通过，V1/V2 ABI 保持；这是规则证据，不是实机同步验收。

## 必须满足的边界

- 各自原生登录与官方连接保留，不读取登录凭据。
- 奖励、背包、任务、解锁及账号进度不由模组生成或补发。
- 未验证游戏版本及原生入口默认停用，账号风险始终显示，不能声称官方认可或零封号风险。
- 保持 V1/V2 ABI，只通过世界 JSON 扩展能力与诊断。
- `full_sync_verified` 保持 `false`，单元测试、解析成功和原生方法返回不能代替真实双客户端验收。
- 先以矿石证明意图、房主原生执行、结果、客机应用和个人世界恢复整条链路，再通过同一机制扩展对象类别。
